1 Cambio de rumbo (importante)

De arquitectura genérica al MEGA PROMPT del curso

El proyecto arrancó (Fase 0) con una arquitectura genérica propuesta por mí: NestJS + Next.js + Prisma + Supabase/Postgres. Al crear la estructura de carpetas encontré que D:\SmartRayco\curso\ ya contenía un plan extremadamente detallado y específico para este mismo tipo de sistema — el proyecto "ISP Manager Fosmikro" — con stack Vue 3 + Vite + Tailwind CSS 4 + Hono + Supabase, comandos SSH exactos para OLT Huawei MA5800 y V-SOL, integración MikroTik vía REST API, TR-069/GenieACS, facturación electrónica SRI Ecuador y WhatsApp Business. El appId de la app móvil (com.szfibersystem.fsmk) coincide con tu dominio de correo, lo que indica que este es el plano real de tu propia infraestructura, no un genérico de curso.

Te pregunté cómo proceder y elegiste adoptar el MEGA PROMPT del curso. En consecuencia:

  • Se eliminó el scaffold NestJS/Next.js/Prisma (no se había hecho commit, sin pérdida).
  • Se reinició con el stack real: Vue 3 + Vite + Tailwind CSS 4 + Supabase, y Hono desde la Fase 2.
  • El plan de fases pasa a ser el de curso/00-indice-general.md (15 fases web + 7 fases Android), en lugar del plan genérico de 5 fases de la propuesta inicial.

5 Lo que falta para probar el login (acción tuya)

⚠ Necesitas crear el proyecto Supabase y completar el .env

Instrucciones paso a paso en docs/architecture/supabase-setup.md. Resumen:

  1. Crear proyecto en app.supabase.com.
  2. cp .env.example .env y completar VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY (Project Settings → API).
  3. Crear un usuario de prueba desde Authentication → Users → Add user.
  4. npm run dev y probar login en http://localhost:5173/login.

6 Nota de seguridad — no bloqueante

npm audit reporta 2 vulnerabilidades (esbuild/vite) del tipo "el servidor de desarrollo de esbuild permite que cualquier sitio web le envíe peticiones y lea la respuesta" — es un problema conocido, limitado al servidor local de desarrollo (no afecta el build de producción). Corregirlo implica saltar a Vite 8 (cambio disruptivo, no probado con Tailwind 4 en este stack). Se deja pendiente como tarea de hardening antes de exponer el entorno de desarrollo públicamente; no afecta el uso normal en localhost.
