SmartRayco · Fase 5

Módulo MikroTik (REST API)

Conexión a RouterOS v7+ vía su REST API, usuarios PPPoE con estado en vivo, conexiones activas y leases DHCP.

1 Qué se construyó

Mismo patrón de seguridad que la Fase 4 (OLT): las credenciales del router nunca llegan al frontend, solo el backend (con service_role) las usa.

CRUD de routers ✓ funcional

  • /mikrotik: registrar, editar, eliminar; botón "Probar conexión"
  • Host, puerto REST (443 por defecto), TLS on/off, usuario, contraseña, zona

Panel del router ✓ funcional

  • /mikrotik/:id: RouterOS, CPU, memoria libre, uptime
  • Tabla de usuarios PPPoE: perfil, conectado (cruzado con /ppp/active), habilitado/deshabilitado
  • Habilitar/deshabilitar un usuario PPPoE con un clic (con confirmación)
  • Tabla de leases DHCP (IP, MAC, hostname, estado)

Endpoints backend

GET    /api/mikrotik-devices                        listar routers
POST   /api/mikrotik-devices                         crear router
PUT    /api/mikrotik-devices/:id                      editar router
DELETE /api/mikrotik-devices/:id                      eliminar router
POST   /api/mikrotik-devices/:id/test                 probar conexion (system/resource)
GET    /api/mikrotik-devices/:id/resource             CPU, RAM, version, uptime
GET    /api/mikrotik-devices/:id/ppp-secrets          usuarios PPPoE
PUT    /api/mikrotik-devices/:id/ppp-secrets/:id       habilitar/deshabilitar
GET    /api/mikrotik-devices/:id/ppp-active           conexiones PPPoE activas
GET    /api/mikrotik-devices/:id/dhcp-leases          leases DHCP
GET    /api/mikrotik-devices/:id/ip-addresses          IPs configuradas

2 Decisión técnica: REST API, no la API binaria clásica

El material del curso tenía dos referencias distintas para MikroTik: la REST API moderna (RouterOS v7+, HTTPS, la que especifica el plan original de fases) y la API binaria clásica (puerto 8728, librería node-routeros, usada en otro documento del curso). Se eligió REST API por ser más simple (HTTP+JSON estándar, sin protocolo binario propio) y por ser la que pide explícitamente el plan de fases acordado.

Requisito en tu router: RouterOS v7 o superior, con el servicio www-ssl (o www sin TLS) habilitado y la REST API activa. Si tu router es v6 o más viejo, avísame para adaptar a la API clásica.

4 Acción tuya para probar esta fase

  1. Aplica la migración supabase/migrations/20260910160000_fase5_mikrotik.sql (Table Editor o SQL Editor, igual que las anteriores).
  2. Confirma que tu RouterOS tiene la REST API habilitada: IP → Services → www-ssl (o www) en estado running.
  3. Ve a /mikrotik en la app, registra tu router (IP, usuario, contraseña) y presiona "Probar conexión".
  4. Pégame el resultado — si tu router usa un puerto o versión distinta a lo esperado, lo ajustamos como hicimos con la OLT.
