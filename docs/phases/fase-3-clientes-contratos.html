SmartRayco · Fase 3

Clientes y contratos

CRUD completo de clientes, numeración automática de contratos (CTR-YYYY-NNNNN) y una vista Kanban por estado con drag-and-drop.

1 Qué se construyó

Criterio de aceptación del curso: "puedo crear clientes, asignarles contratos y ver el Kanban" — cumplido y verificado en el flujo de compilación (sección 3); falta tu prueba manual end-to-end una vez tengas Supabase con datos.

Clientes ✓ funcional

  • /clientes — tabla con nombre, documento, teléfono, zona, estado (badge de color)
  • Modal crear/editar: documento, nombres, teléfono, correo, dirección, zona, estado
  • Eliminar con confirmación
  • /clientes/:id — perfil con datos + historial de contratos

Contratos ✓ funcional

  • Botón "Nuevo contrato" desde el perfil del cliente: elige plan (precargado desde plans), mensualidad, día de corte, método de pago
  • Numeración automática: trigger SQL asigna CTR-2026-00001, CTR-2026-00002... al insertar, sin intervención del frontend
  • /contratos/kanban — 3 columnas (Activos / Suspendidos / Cancelados), arrastrar tarjeta = cambio de estado con confirmación

Decisión de arquitectura aplicada

Todo este CRUD llama directo a Supabase desde el frontend (no pasa por el backend Hono), respetando las políticas RLS por rol definidas en la Fase 2. Esto sigue la arquitectura del curso: Hono se reserva para operaciones con SSH o credenciales privadas (OLT, MikroTik, SRI) — no para CRUD simple.

⚠ Aplicar la nueva migración

Igual que en la Fase 2: pega supabase/migrations/20260910130000_fase3_clientes_contratos.sql en el SQL Editor de Supabase, o corre supabase db push si ya vinculaste el proyecto con la CLI.
