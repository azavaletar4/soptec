Módulo OLT — ZTE C300

CRUD de OLTs, cliente SSH interactivo genérico, y comandos/parsers específicos para tu equipo real (ZTE C300) — no Huawei como proponía el material original del curso.

1 Cambio de marca durante la fase

⚠ El curso solo documenta Huawei y V-SOL — tu OLT es ZTE

A mitad de esta fase confirmaste que tu OLT real es una ZTE C300. El material de referencia (curso/04-administracion-olt.md, curso/05-gestion-ont.md) solo cubre Huawei MA5800 y V-SOL con comandos verificados contra esos equipos reales. Para ZTE no hay ese respaldo, así que los comandos SSH implementados aquí se basan en las convenciones generales y públicamente conocidas de la CLI ZXA10 C300 (estilo Cisco: enable / configure terminal / interface gpon-olt_S/L/P), con un nivel de confianza menor que si fuera Huawei.

2 Qué se construyó

Seguridad y arquitectura ✓ nuevo

  • Primera vez que Hono valida autenticación: middleware que verifica el JWT de Supabase y el rol del usuario antes de ejecutar cualquier comando SSH
  • olt_devices / olt_onts: RLS habilitado sin políticas — inaccesibles directo desde el frontend, solo vía backend con service_role
  • La contraseña SSH de la OLT nunca se devuelve en ningún GET

Cliente SSH ✓ funcional (infraestructura)

  • server/src/ssh/client.ts: shell interactivo genérico — detecta el prompt, pagina automáticamente, responde confirmaciones "(y/n)" y contraseñas de "enable" si hacen falta
  • Reutilizable para futuras marcas (si algún día agregas otra OLT distinta a la ZTE)

CRUD de OLTs ✓ funcional

  • /olt: registrar, editar, eliminar OLTs; botón "Probar conexión"
  • Formulario con host, puerto SSH, usuario, contraseña, zona

Gestión de ONTs funcional, comandos sin validar en hardware

  • /olt/:id: seleccionar slot/puerto → sincronizar ONTs desde la OLT (cache local)
  • Registrar ONT nueva (ID auto-detectado o manual, tipo de ONU, VLAN, descripción)
  • Activar / desactivar / eliminar ONT, lectura de señal óptica (Rx/Tx)

3 Comandos ZTE implementados (a validar)

Conectar / probar:     enable → show version
Listar ONTs de un puerto:  enable → show gpon onu state gpon-olt_{shelf}/{slot}/{port}
Registrar ONT:          enable → configure terminal → interface gpon-olt_.../...
                        onu {id} type {tipo} sn {serial} → exit
                        interface gpon-onu_.../...:{id} → tcont/gemport/service-port → exit
Activar/Desactivar:     onu {id} admin-state enable|disable
Eliminar:               no onu {id}
Senal optica:           show pon power attenuation gpon-onu_.../...:{id}

🛑 No probar comandos de escritura contra un puerto con clientes activos

Antes de usar "Registrar ONT", "Activar/Desactivar" o "Eliminar" en producción:

  1. Verifica a mano por SSH/consola que los comandos de lectura (show gpon onu state, show pon power attenuation) devuelven el formato que esperan los parsers en server/src/ssh/zteParsers.ts — ajusta los regex si tu firmware difiere.
  2. Prueba los comandos de escritura primero en un puerto de pruebas o con una ONU de repuesto.
  3. Si algo no coincide, dime el output real de tu OLT y ajusto los comandos/parsers.

4 Bugs de infraestructura encontrados y corregidos

Esta fase destapó dos problemas reales en lo ya construido, no relacionados con ZTE:

ProblemaImpactoCorrección
supabaseAdmin.ts creaba el cliente Supabase al cargar el módulo Si faltaba SUPABASE_SERVICE_ROLE_KEY, todo el backend se caía al iniciar (hasta /api/health) Cliente perezoso (Proxy): solo falla, con mensaje claro, la ruta que realmente necesita la service_role key
vite.config.ts tenía el proxy /api fijo a localhost:3001 Desincronizado del PORT=3000 real de Hono → las llamadas del frontend al backend fallaban en desarrollo Ambos ahora leen la misma variable PORT del .env

6 Acción tuya para poder probar esta fase

  1. Completa en tu .env: SUPABASE_SERVICE_ROLE_KEY y JWT_SECRET (Project Settings → API, ver docs/architecture/supabase-setup.md).
  2. Aplica la migración supabase/migrations/20260910140000_fase4_olt.sql.
  3. Reinicia npm run dev para que el backend cargue las nuevas variables.
  4. Ve a /olt, registra tu ZTE C300 (IP, usuario, contraseña SSH) y usa "Probar conexión" — con eso confirmamos si enable + show version funcionan tal cual contra tu equipo.
  5. Pégame el resultado (el output real, o el error) para ajustar los comandos si hace falta.
