Corresponde a la Fase 2 — Backend Hono y base de datos del curso. Criterio de aceptación: "el servidor Hono responde en /api/health" — cumplido y verificado (sección 3).

Backend Hono ✓ funcional

  • server/src/index.ts — servidor Hono sobre Node.js (ESM, vía tsx)
  • server/src/routes/health.ts — GET /api/health
  • server/src/lib/supabaseAdmin.ts — cliente con service_role key (bypassea RLS), listo para Fase 3
  • npm run dev levanta frontend (Vite, 5173) + backend (Hono, 3001) en paralelo con concurrently

Base de datos ✓ migración lista

  • supabase/migrations/20260910120000_fase2_esquema_inicial.sql
  • Tablas: profiles, zones, plans, clients, service_contracts
  • Tipos enum: user_role, connection_technology, document_type, client_status, contract_status
  • Trigger handle_new_user: crea el profile al registrarse en Supabase Auth
  • RLS habilitado en las 5 tablas, con función helper current_user_role()

2 Modelo de datos

profiles (id = auth.users.id)
  role: SUPERADMIN | ADMIN | TECNICO_RED | SOPORTE | FACTURACION | CLIENTE

zones
  id · name · description

plans
  id · name · download_speed · upload_speed · price
  technology (fiber|radio|cable|dsl) · mikrotik_profile · is_active

clients
  id · zone_id (FK zones) · document_type · document_number (unico)
  first_name · last_name · phone · email · status (prospect|active|suspended|retired)

service_contracts
  id · contract_number (numeracion automatica -> Fase 3)
  client_id (FK clients) · plan_id (FK plans)
  monthly_fee · status (active|suspended|cancelled) · billing_day (1-28)

4 Acción tuya: aplicar la migración

⚠ La tabla aún no existe en tu Supabase hasta que la apliques

Dos formas, detalladas en docs/architecture/supabase-setup.md:

  1. Rápida: copiar el contenido de la migración y pegarlo en el SQL Editor del dashboard de Supabase.
  2. Con CLI (recomendada de aquí en adelante): supabase link --project-ref TU_PROJECT_REF y luego supabase db push.

Después, completa SUPABASE_SERVICE_ROLE_KEY y JWT_SECRET en tu .env, y crea tu primer SUPERADMIN (pasos en el mismo documento).
