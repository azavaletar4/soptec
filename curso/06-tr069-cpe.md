## 6.0 ¿Qué es TR-069?

TR-069 (también conocido como CWMP, *CPE WAN Management Protocol*) es un estándar definido por el Broadband Forum que permite a un operador de internet gestionar remotamente los equipos instalados en los domicilios de sus clientes, llamados CPEs (*Customer Premises Equipment*): routers, ONTs con WiFi integrado, módems ADSL, etc.

### Actores del protocolo

```
ACS (Auto Configuration Server)
     ↕  CWMP (HTTP/S, puerto 7547)
CPE (router / ONT del cliente)
```

- **ACS** — el servidor de gestión. Es quien inicia sesiones o responde llamadas del CPE.
- **CPE** — el equipo en casa del cliente. Se registra en el ACS enviando mensajes *Inform* periódicos.
- **Inform** — el latido del CPE. Cada cierto intervalo (p. ej. 300 s) el CPE llama al ACS, informa su estado y recibe tareas pendientes.

### ACS usado en este proyecto: GenieACS

GenieACS es un ACS open source escrito en Node.js con MongoDB como almacén de datos. Es gratuito, maduro y ampliamente usado en ISPs pequeños y medianos.

- Repositorio oficial: https://github.com/genieacs/genieacs
- Licencia: AGPL-3.0

## 6.1 Instalación de GenieACS

### Requisitos previos

| Componente | Versión recomendada |
|---|---|
| Node.js | 18 LTS o superior |
| MongoDB | 4.4 – 7.x |
| Sistema operativo | Ubuntu 22.04 / Debian 12 |

### Puertos que expone GenieACS

| Puerto | Servicio | Descripción |
|---|---|---|
| **7547** | CWMP | Los CPEs se conectan aquí para sus sesiones Inform |
| **7557** | NBI API | API REST interna (North Bound Interface) — usada por fosmikro |
| **7567** | FS (File Server) | Servidor de archivos: firmwares, configs |
| **3000** | UI | Interfaz web de GenieACS |

> **Nota:** El puerto 7547 debe ser accesible desde la red de los clientes (IP pública o a través del túnel Cloudflare). El puerto 7557 solo debe ser accesible desde el servidor de fosmikro (localhost o red interna).

### Instalación con npm (global)

```bash
# 1. Instalar GenieACS globalmente
npm install -g genieacs

# 2. Crear usuario del sistema (opcional pero recomendado)
sudo useradd -r -s /bin/false genieacs
sudo mkdir -p /opt/genieacs /opt/genieacs/ext
sudo chown genieacs /opt/genieacs/ext

# 3. Archivo de configuración /opt/genieacs/genieacs.env
cat <<EOF | sudo tee /opt/genieacs/genieacs.env
GENIEACS_CWMP_ACCESS_LOG_FILE=/var/log/genieacs/cwmp-access.log
GENIEACS_NBI_ACCESS_LOG_FILE=/var/log/genieacs/nbi-access.log
GENIEACS_FS_ACCESS_LOG_FILE=/var/log/genieacs/fs-access.log
GENIEACS_UI_ACCESS_LOG_FILE=/var/log/genieacs/ui-access.log
GENIEACS_DEBUG_FILE=/var/log/genieacs/debug.yaml
GENIEACS_EXT_DIR=/opt/genieacs/ext
EOF

sudo mkdir -p /var/log/genieacs
sudo chown genieacs /var/log/genieacs
```

### Servicios systemd

Crear cuatro archivos de servicio: `genieacs-cwmp`, `genieacs-nbi`, `genieacs-fs`, `genieacs-ui`. Ejemplo para CWMP:

```ini
# /etc/systemd/system/genieacs-cwmp.service
[Unit]
Description=GenieACS CWMP
After=network.target

[Service]
User=genieacs
EnvironmentFile=/opt/genieacs/genieacs.env
ExecStart=/usr/bin/genieacs-cwmp
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Repetir el mismo patrón para `genieacs-nbi` (`ExecStart=/usr/bin/genieacs-nbi`), `genieacs-fs` y `genieacs-ui`.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now genieacs-cwmp genieacs-nbi genieacs-fs genieacs-ui
sudo systemctl status genieacs-cwmp
```

### Alternativa: PM2 (en el mismo servidor que fosmikro)

Si el servidor ya usa PM2 para fosmikro, se puede levantar GenieACS con PM2:

```bash
pm2 start genieacs-cwmp --name genieacs-cwmp
pm2 start genieacs-nbi  --name genieacs-nbi
pm2 start genieacs-fs   --name genieacs-fs
pm2 start genieacs-ui   --name genieacs-ui
pm2 save
```

## 6.2 Tabla `tr069_devices` en Supabase

El módulo TR-069 de fosmikro usa dos migraciones para persistir los dispositivos gestionados.

### Migración 029: tabla principal

Archivo: `supabase/migrations/029_tr069_devices.sql`

```sql
CREATE TABLE IF NOT EXISTS tr069_devices (
  id                  UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  genieacs_id         TEXT        NOT NULL UNIQUE,  -- formato: "OUI-ProductClass-SerialNumber"
  cpe_oui             TEXT,                         -- ej. "00D09E"
  cpe_product_class   TEXT,                         -- ej. "EchoLife HG8145X6"
  cpe_serial          TEXT        NOT NULL,         -- ej. "48575443A1234567"
  service_contract_id UUID        REFERENCES service_contracts(id) ON DELETE SET NULL,
  notes               TEXT,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**Diseño importante:**

- `genieacs_id` sigue el formato estándar de GenieACS: `OUI-ProductClass-SerialNumber` (ej. `00D09E-HG8145X6-48575443A1234567`).
- Cada CPE puede vincularse a un contrato de servicio (`service_contract_id`). Un contrato tiene como máximo un CPE TR-069 (índice UNIQUE condicional).
- RLS habilitado: solo usuarios autenticados pueden acceder.

### Migración 030: columnas de caché

Archivo: `supabase/migrations/030_tr069_status_columns.sql`

```sql
ALTER TABLE tr069_devices
  ADD COLUMN IF NOT EXISTS last_seen_at      TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS model_name        TEXT,
  ADD COLUMN IF NOT EXISTS firmware_version  TEXT,
  ADD COLUMN IF NOT EXISTS wan_ip            TEXT,
  ADD COLUMN IF NOT EXISTS ssid              TEXT;
```

**Propósito del caché:** GenieACS corre en Docker o un proceso local. Si está offline, fosmikro sigue mostrando los últimos datos conocidos de cada CPE directamente desde Supabase, sin depender de que GenieACS esté disponible.

## 6.3 Vista TR-069 en fosmikro (web)

### Archivos

| Archivo | Descripción |
|---|---|
| `src/views/tr069/Tr069DevicesView.vue` | Lista de dispositivos con estado en tiempo real |
| `src/views/tr069/Tr069DeviceShow.vue` | Detalle completo: Info, WAN, WiFi, Faults, Firmware |
| `src/services/genieacs.ts` | Cliente TypeScript para la NBI API de GenieACS |

### Lista de dispositivos (`Tr069DevicesView.vue`)

La vista carga datos de dos fuentes en paralelo y los fusiona:

1. **GenieACS NBI** (`GET /devices`) — datos en vivo: `_lastInform`, IP WAN PPPoE, SSID.
2. **Supabase** (`tr069_devices`) — caché persistente: modelo, IP WAN, SSID, contrato vinculado.

Si GenieACS está offline se activa el **modo caché** automáticamente, mostrando un aviso en ámbar.

**Estados de un dispositivo:**

| Estado | Criterio | Color |
|---|---|---|
| Online | `_lastInform` hace menos de 48 h | Verde |
| Sin inform | Entre 48 h y 30 días | Ámbar |
| Offline | Más de 30 días sin inform | Gris |

**Funcionalidades de la lista:**

- Búsqueda por ID GenieACS, modelo, serial, IP WAN, SSID, nombre de cliente o número de contrato.
- Vincular / desvincular un CPE a un contrato de servicio.
- Eliminar un dispositivo (del ACS y de Supabase).
- Refresco automático silencioso cada 60 segundos.
- Sincronización automática con Supabase al montar la vista.

**Panel "Configurar ACS":**

Desde la vista de lista se puede instalar directamente en GenieACS la provision y el preset `auto-monitor`, que ordenan a cada CPE reportar sus parámetros clave en cada sesión Inform. El script que se instala:

```javascript
declare("InternetGatewayDevice.DeviceInfo.Manufacturer",           {value: Date.now()});
declare("InternetGatewayDevice.DeviceInfo.ModelName",              {value: Date.now()});
declare("InternetGatewayDevice.DeviceInfo.SerialNumber",           {value: Date.now()});
declare("InternetGatewayDevice.DeviceInfo.SoftwareVersion",        {value: Date.now()});
declare("InternetGatewayDevice.DeviceInfo.UpTime",                 {value: Date.now()});
declare("InternetGatewayDevice.ManagementServer.ConnectionRequestURL",   {value: Date.now()});
declare("InternetGatewayDevice.ManagementServer.PeriodicInformInterval", {value: Date.now()});
declare("InternetGatewayDevice.WANDevice.1.WANConnectionDevice.1.WANIPConnection.1.ExternalIPAddress", {value: Date.now()});
declare("InternetGatewayDevice.WANDevice.1.WANConnectionDevice.1.WANIPConnection.1.ConnectionStatus",  {value: Date.now()});
declare("InternetGatewayDevice.LANDevice.1.WLANConfiguration.1.SSID",    {value: Date.now()});
declare("InternetGatewayDevice.LANDevice.1.WLANConfiguration.1.Channel", {value: Date.now()});
```

### Vista de detalle (`Tr069DeviceShow.vue`)

Organizada en cuatro pestañas:

**Pestaña Información**

Muestra: Fabricante, Modelo, Número de Serie, Clase de Producto, Hardware Version, Firmware Version, UpTime, ID GenieACS, fecha de registro, fecha del último Inform, intervalo Inform, Connection Request URL.

**Pestaña WAN**

- Detecta automáticamente PPPoE (`WANPPPConnection`) o IP/DHCP (`WANIPConnection`).
- PPPoE tiene prioridad sobre IP (porque en FTTH la `WANIPConnection` es solo la interfaz subyacente).
- Muestra: IP WAN, Gateway, DNS, MAC, usuario PPPoE, último error de conexión.
- Formulario de edición (requiere permiso `canEdit`): cambiar usuario/contraseña PPPoE, cambiar tipo DHCP/Estático.

**Pestaña WiFi / LAN**

- Detecta múltiples radios (2.4 GHz / 5 GHz) por índice relativo o por parámetros del fabricante (`X_HW_BAND`, `X_CMCC_RFBand`).
- Muestra SSID actual, canal, tipo de beacon, cifrado.
- Formulario de edición: SSID, contraseña WPA (mínimo 8 caracteres), canal, seguridad (WPA/WPA2/WPA+WPA2/Abierta).
- Las tareas se encolan con polling cada 15 s para confirmar aplicación.

**Pestaña Faults**

Lista errores registrados por GenieACS para el dispositivo.

**Acciones del panel lateral**

- Actualizar parámetros (fuerza sesión TR-069 inmediata).
- Reiniciar dispositivo (reboot RPC).
- Actualizar Firmware (modal con dos pestañas: seleccionar firmware existente en ACS o subir archivo nuevo).

## 6.4 Sincronización TR-069

### Endpoint Hono: `POST /api/tr069-sync`

Archivo: `server/src/routes/tr069sync.ts`

El endpoint realiza la sincronización **GenieACS → Supabase** en tres pasos:

1. Consulta la NBI API de GenieACS: `GET http://127.0.0.1:7557/devices`
2. Carga los registros existentes en `tr069_devices` de Supabase.
3. Para cada dispositivo que ya existe en Supabase, hace un `PATCH` actualizando las columnas de caché: `last_seen_at`, `model_name`, `firmware_version`, `wan_ip`, `ssid`.

La extracción de IP WAN prioriza PPPoE antes que WANIPConnection, igual que la lógica del frontend.

```
Respuesta exitosa:
{ ok: true, synced: 5, total: 12 }
```

Donde `synced` es cuántos registros fueron actualizados y `total` es cuántos dispositivos reportó GenieACS.

**La sincronización se activa:**

- Automáticamente al montar la vista de lista (background, sin bloquear).
- Manualmente con el botón "Actualizar" de la vista.

### Proxy GenieACS: `/api/genieacs/*`

Archivo: `server/src/routes/genieacs.ts`

Para que el frontend pueda llamar a la NBI API sin exponer el puerto 7557 directamente a internet, existe un proxy reverso en Hono que reenvía todas las peticiones autenticadas al ACS local:

```
Navegador → POST /api/genieacs/devices/{id}/tasks
         → Hono (authMiddleware valida JWT Supabase)
         → fetch http://127.0.0.1:7557/devices/{id}/tasks
         → GenieACS NBI
```

Esto garantiza que solo usuarios autenticados de fosmikro puedan ejecutar comandos en los CPEs.

### Cliente TypeScript: `src/services/genieacs.ts`

Expone funciones tipadas para todas las operaciones sobre la NBI API:

| Función | Descripción |
|---|---|
| `listDevices(filter?, projection?)` | Lista dispositivos con filtro MongoDB opcional |
| `getDevice(id)` | Obtiene un dispositivo por su ID completo |
| `createTask(deviceId, task, opts)` | Crea una tarea (reboot, setParameterValues, download, etc.) |
| `isTaskPending(taskId)` | Verifica si una tarea sigue en cola |
| `deleteDevice(id)` | Elimina un dispositivo del ACS |
| `putProvision(name, script)` | Instala o actualiza una provision JS |
| `putPreset(name, preset)` | Instala o actualiza un preset |
| `listFaults(deviceId?)` | Lista faults globales o de un dispositivo |
| `rebootDevice(id)` | Atajo: tarea reboot |
| `refreshDevice(id)` | Atajo: tarea getParameterValues completo |
| `setWifi(id, ssid, key)` | Atajo: cambiar SSID y contraseña |
| `listFiles(fileType?)` | Lista archivos en el FS del ACS |
| `uploadFile(name, data, meta)` | Sube un firmware o config al ACS |
| `firmwareUpgrade(deviceId, fileId)` | Envía tarea de actualización de firmware |
| `paramVal(param)` | Extrae el valor legible de un `GenieParam` |

**Comportamiento de tareas:**

- Si el CPE está conectado en ese momento, GenieACS envía el comando inmediatamente y devuelve HTTP 200/204 (tarea ejecutada).
- Si el CPE no está conectado, GenieACS devuelve HTTP 202 con el ID de la tarea en cola. El frontend hace polling cada 15 segundos para confirmar la aplicación.

## 6.5 Perfil TR-069 en OLT (línea y servicio)

Los routers del cliente que se conectan vía FTTH se provisionan desde la OLT (Huawei MA5800). El `ont-lineprofile` es el lugar donde se configura el comportamiento TR-069 del ONT/CPE.

La tabla `olt_line_profiles_info` (migración `034_olt_profiles.sql`) almacena los perfiles escaneados desde la OLT:

- `profile_id` — ID del perfil en la OLT.
- `profile_name` — nombre descriptivo.
- `mapping_description` — describe el mapeo de GEM ports y T-CONTs.
- `source` — `system` (creado por la OLT) o `managed` (gestionado desde fosmikro).

**Configuración TR-069 en el perfil de línea de la OLT:**

En la CLI de la MA5800, dentro de un `ont-lineprofile`, se configura el modo TR-069 del ONT:

```
ont-lineprofile gpon profile-id 10 profile-name "TR069-FTTH"
  tr069-server enable
  tr069-server acs-url http://TU_IP_PUBLICA:7547
  tr069-server acs-username admin
  tr069-server acs-password tu_password
  tr069-server periodic-inform enable
  tr069-server periodic-inform interval 300
commit
```

Con esta configuración, cuando se registra un nuevo ONT con ese perfil de línea, el ONT recibe automáticamente la URL del ACS y comienza a enviar mensajes Inform al GenieACS.

## 6.6 Vista TR-069 en fsMk (app móvil)

Archivo: `D:/fsmk/src/views/tr069/Tr069View.vue`

La app móvil ofrece una versión simplificada del módulo TR-069, optimizada para el técnico en campo. Usa la misma API del servidor fosmikro.

### Vista lista (pantalla principal)

- Carga todos los dispositivos desde GenieACS (con proyección limitada: `_id`, `_lastInform`, `DeviceInfo.ModelName`, `DeviceInfo.SerialNumber`, `WANDevice`).
- Cruza con Supabase para obtener nombre del cliente.
- Muestra por cada dispositivo: modelo, nombre del cliente, IP WAN, SSID, indicador online/offline.
- **Online en la app móvil:** si `_lastInform` tiene menos de 10 minutos (criterio más estricto que en la web, pensado para uso en campo).

Si el servidor no está configurado muestra un mensaje guiando al técnico a configurar la URL del servidor en Menú → Configurar servidor.

### Vista detalle (al tocar un dispositivo)

Cuatro pestañas adaptadas a pantalla pequeña:

**Info** — Modelo, Fabricante, Serial, Firmware, Hardware, Uptime, Último inform, ID GenieACS. Muestra los faults del dispositivo con opción de limpiarlos individualmente o todos.

**WAN** — Estado de conexión (PPPoE o DHCP/Estática), IP WAN, Gateway, DNS, MAC, usuario PPPoE.

**WiFi** — SSID y canal por radio. Formulario de edición de SSID y contraseña WPA (solo edita el primer radio).

**Acciones** — Botón de reinicio (reboot TR-069), botón de refresco de parámetros, sección con URL del ACS, intervalo de inform y Connection Request URL.

## 6.8 Prompt Claude para crear el módulo TR-069 completo

El siguiente prompt puede usarse para reproducir o extender el módulo TR-069 de fosmikro en un nuevo proyecto con el mismo stack (Vue 3 + TypeScript + Hono + Supabase + GenieACS).

---

```
Crea el módulo TR-069 completo para un ISP Manager con el siguiente stack:
- Frontend: Vue 3 + TypeScript + Vite + Tailwind CSS 4
- Backend: Hono (Node.js) con autenticación JWT via Supabase
- Base de datos: Supabase PostgreSQL con RLS
- ACS: GenieACS corriendo localmente en http://127.0.0.1:7557 (NBI API)

=== BASE DE DATOS ===

Crea dos migraciones SQL:

1. Tabla `tr069_devices`:
   - id UUID PRIMARY KEY
   - genieacs_id TEXT NOT NULL UNIQUE  (formato: OUI-ProductClass-SerialNumber)
   - cpe_oui TEXT, cpe_product_class TEXT, cpe_serial TEXT NOT NULL
   - service_contract_id UUID REFERENCES service_contracts(id) ON DELETE SET NULL
   - notes TEXT
   - created_at, updated_at TIMESTAMPTZ
   - RLS: solo usuarios autenticados
   - Trigger updated_at automático
   - Índice UNIQUE condicional: un contrato = máximo un CPE

2. Columnas de caché (ALTER TABLE):
   - last_seen_at TIMESTAMPTZ
   - model_name TEXT
   - firmware_version TEXT
   - wan_ip TEXT  (con índice)
   - ssid TEXT

=== BACKEND HONO ===

1. Proxy `/api/genieacs/*`:
   - Requiere authMiddleware (JWT Supabase)
   - Reenvía todas las peticiones a http://127.0.0.1:7557
   - Timeout 60 s, maneja errores de conexión con 502

2. Endpoint `POST /api/tr069-sync`:
   - Requiere authMiddleware
   - Consulta GET http://127.0.0.1:7557/devices
   - Carga registros existentes en tr069_devices
   - Para cada dispositivo que exista en Supabase, hace PATCH actualizando:
     last_seen_at, model_name, firmware_version, wan_ip (PPPoE primero, luego IP), ssid
   - Devuelve { ok, synced, total }
   - Multi-tenant: filtra por tenant_id del JWT

=== CLIENTE TYPESCRIPT ===

Archivo `src/services/genieacs.ts` con:
- Interfaz `GenieDevice` completa (DeviceInfo, ManagementServer, WANDevice, LANDevice)
- Interfaz `GenieTask` y `GenieTaskResult` (queued: boolean, taskId: string)
- Interfaz `GenieFile` para firmwares
- Función `nbi<T>(path, options?)`: fetch autenticado a /api/genieacs
- `listDevices(filter?, projection?)`, `getDevice(id)`
- `createTask(deviceId, task, { timeout, connectionRequestTimeout })`:
  - 202 → { queued: true, taskId }
  - 204/200 → { queued: false, taskId: '' }
- `isTaskPending(taskId)`: consulta /tasks para saber si sigue en cola
- `putProvision(name, script)`, `putPreset(name, preset)`
- `listProvisions()`, `listPresets()`
- `listFaults(deviceId?)`
- `rebootDevice(id)`, `refreshDevice(id)`, `setWifi(id, ssid, key)`
- `listFiles(fileType?)`, `uploadFile(name, blob, meta)`, `deleteFile(id)`
- `firmwareUpgrade(deviceId, fileId)` con timeout 30 s
- `paramVal(param)`: extrae _value como string

=== VISTA LISTA (Vue) ===

`Tr069DevicesView.vue`:
- Carga en paralelo: GenieACS NBI (datos en vivo) + Supabase (caché + contratos)
- Fusiona los dos conjuntos en un array unificado de `Row`
- Si GenieACS falla: modo caché, aviso en ámbar
- Estados: online (<48 h), stale (48 h–30 d), offline (>30 d)
- Extracción IP WAN: PPPoE primero, fallback a WANIPConnection
- Refresco automático silencioso cada 60 s (setInterval, limpiado en onUnmounted)
- Sincronización automática al montar (POST /api/tr069-sync)
- Búsqueda por: ID, modelo, serial, IP WAN, SSID, nombre cliente, nro. contrato
- Acciones por fila: Ver detalle, Vincular a contrato (modal), Desvincular, Eliminar
- Panel "Configurar ACS": instalar provision y preset "auto-monitor" en GenieACS
  - Provision: declare() de todos los parámetros clave con {value: Date.now()}
  - Preset: { weight: 0, precondition: 'true', configurations: [{type: 'provision', name: 'auto-monitor'}] }

=== VISTA DETALLE (Vue) ===

`Tr069DeviceShow.vue`, recibe prop `id: string` (genieacs_id):
- Carga en paralelo: getDevice(id), listFaults(id), registro Supabase (contrato vinculado)
```
